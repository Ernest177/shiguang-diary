# 关键决策与代价

## 1. 本地数据库作为正式数据源

**背景**：隐私优先，清理浏览器缓存后仍需保留日记。

**决定**：本地服务统一读写 SQLite，浏览器只存草稿及界面偏好；原文、版本、派生分析、行动和来源独立建模。

**收益**：事务与外键可检查，备份迁移路径明确。

**代价**：需运行本地进程并保管数据目录，未实现日记加密。

**重审条件**：手机远程访问、多用户或跨设备同步。

## 2. 原文先保存，AI 异步处理

**背景**：模型会超时、限流或未配置，记录不能依赖外部服务。

**决定**：原文与版本先提交，再通过持久化队列分析；未配置等待，失败有限重试，重启恢复运行中任务。

**收益**：核心记录与网络故障解耦，失败状态可见。

**代价**：需要等待、运行、失败和过期状态；单线程限制吞吐。

**重审条件**：实测积压影响体验，再引入并发与限流协调。

## 3. 版本与任务票据共同保护写回

**背景**：编辑、重跑与旧请求交错。

**决定**：请求绑定版本和票据，在锁与事务边界内再核对；每日回顾比较上下文签名。

**收益**：失效结果不会覆盖新输入。

**代价**：可能丢弃已付费结果，需要防抖降低无效调用。

**重审条件**：多进程或多设备时升级数据库协调机制。

## 4. 行动状态独立于模型结果

**背景**：模型提议行动，用户拥有最终决定权。

**决定**：行动 ID、标题指纹、来源关系和用户修改保护；被拒绝的建议保留抑制状态。

**收益**：保留修正，避免取消后复活，可追溯、可撤销。

**代价**：指纹只解决相同标题；语义合并可能失误，用户修改后自动关闭更保守。

**重审条件**：完成语义评估后，再提高自动化程度。

## 5. 提示词与应用校验配合

**背景**：要求返回 JSON 无法保证格式、依据和逻辑。

**决定**：模板明确字段，应用校验版本、类型、引用、来源和少量保守规则；失败拒绝落库并可重试。

**收益**：部分错误变成可见失败，避免静默污染。

**代价**：引用存在不等于结论正确，当前未启用提供方原生 JSON Schema 约束。

**重审条件**：增加提供方参数与真实评估，避免为一个厂商破坏其他服务兼容性。

## 6. 标准库实现第一版

**背景**：本机运行、功能范围有限，希望克隆即可验证。

**决定**：Python 标准库与原生前端，无第三方运行依赖。

**收益**：无需构建和安装依赖，数据流易于跟踪。

**代价**：内置 HTTP 服务只用于本机，前端状态维护需人工约束，尚无独立桌面安装器。

**重审条件**：状态复杂度超过维护能力时引入前端框架；对外服务时重新选择服务器和身份模型。
