# 借鉴已有项目，补强拾光

拾光面向单人长期记录。现有的原文、来源校验、增量提取与本地缓存继续沿用；本次主要补强“有限的画像上下文怎样兼顾不同经历”与“完整流程是否更省、更可靠”。

## 画像怎样选择线索

`app/memory_selection.py` 使用确定性的本机规则，不调用判断模型：

1. 先为用户确认与修正、明确日期中较新的记录、长期线索及较早的经历留出位置。
2. 覆盖不同线索类别，再优先补足用户决定、独立来源与不同时间范围。
3. 最多选择 24 条，序列化的记忆列表不超过 24,000 字符；单条完整内容放不下时跳过，不从中间截断修正。字符预算不是精确 Token 预算。

日期取自原文来源的明确年份、月份或日期。“大学期间”“最近”等表达保持原样，不用导入时间代替发生时间。这套规则用于覆盖范围，不评判人生重要性，也不证明归纳正确。

所有记忆与原文继续保存。不同日期出现相似感受时，各自的来源和发生次数仍保留。选择某次画像的输入，与判断经历是否重复是两件独立的事。

画像缓存绑定选中的内容与选择协议。只有可用总数等覆盖计数变化时，在本机更新显示；选中内容改变时才需要新画像。来源修改、排除、删除和用户修正仍经过既有失效机制。

## 完整流程怎样比较

`python -m evals.pipeline` 默认只用公开合成场景和手写替身。两种策略分别创建空白临时数据库，走实际保存、队列、来源校验、成长积累、缓存和呈现流程。

基线为“始终 AI”，仍保留当前版本的输入精简与缓存；候选为“按需整理”，增加生成前判断和生成后呈现判断。因此它回答的是这两种策略在当前版本里的差异，不声称重现所有历史版本。

报告包含全部调用的用途、重试次数、输出和用量；逐例检查原文保存、队列完成、重复检查缓存、跨日期成长记录及所请求月报是否可用。旧的行动准确率、日期、引用和误关闭评测继续独立运行。

生成后呈现判断在本机执行，不额外消耗模型 Token，也不退还已生成内容的费用。省下当前调用依靠生成前跳过；避免重复处理依靠有效缓存。真实 Token、费用和质量都必须实际测量，不能由字符数推算出已实现的收益。

默认离线报告中的 Token 和费用为未知。显式真实实验只发送这些合成文本，独立记账，报告不写入正式日记的用量页面。失败、重试和缺失用量均保留；服务方缓存可能影响先后两次实验的价格，需要重复实验并审阅缓存明细。

当前没有引入向量数据库、Redis 或额外的判断模型。单机数据规模下，这些组件的部署和维护成本尚缺少足够收益证据；后续可以在相同样例上评估它们，再决定是否接入。
