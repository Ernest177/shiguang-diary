# 图片与视频：让日记保留现场

写一段文字，把光标留在想插图的位置，点击「＋ 图片 / 视频」。可以多选文件，也可以拖入文件或粘贴图片。继续写下后文，打开「查看图文预览」即可检查顺序；「移到光标」和前移按钮可调整位置。保存后的照片可以放大，视频使用浏览器播放器，可下载原件。

支持 JPG / PNG / GIF / WebP（单个最大 25 MB）与 MP4 / WebM / MOV（单个最大 512 MB），每条最多 60 个。文件头决定类型，不只相信后缀。视频是否能播放取决于浏览器与编码；不转码原件，不支持的编码提供下载入口。纯附件日记也可保存，且不调用 AI。当前仅支持日记附件，成长经历补录仍为文字。

编辑预览、正文和下载名称自动附加日记所属日期，例如 `密室合影_01_2026-10-25.jpg`。补记取补记日期，日期修改后预览随即更新，保存后当前记录的下载也同步；不使用上传日期或推测拍摄日期。悬停名称可查看原始文件名。同一素材用于多天时，各次引用保留各自的日期，历史版本按当时的所属日期命名。

命名从保留的原始名称计算，不反复修改上一次生成的名字，也不搬动浏览器上传前的源文件。原件的内容标识继续稳定，日期作为日记与素材之间的关系，不需要重存原件或额外调用模型。原始名称中自带的其他日期会保留，避免抹掉可能有意义的拍摄时间。下载扩展名以实际识别的文件类型为准。

## 图片智能命名

在「偏好与设置 → 图片智能命名」开启一次，复用上方已配置且支持视觉输入的模型与密钥。此开关默认关闭，独立于文字整理。阿里云使用 [Chat Completions 兼容视觉接口](https://help.aliyun.com/zh/model-studio/vision/)，发送 `image_url` 的 JPEG Data URI；纯文本模型不会因此获得看图能力，服务拒绝时保留原名。

上传先在本机识别乱码、相机编号、纯数字等名称；例如 `128jfcfsad.jpg` 可以得到 `室内多人合影_2026-10-24.jpg`，已有「毕业合影」等名称不触发请求。文件名判别是保守规则，不保证识别全部乱码；附件旁「识图命名」允许主动处理遗漏。「改名」可直接修正或留空恢复原始名称，修改要随日记保存。

浏览器将可见画面重新绘制为 JPEG 预览，长边不超过 768 像素，过大时降到 512 / 384；服务端限制预览为 256 KiB、拒绝外部图片 URL、超尺寸及 EXIF / XMP。原始文件不改变，视频不送入模型；请求不包含原始文件名、路径、哈希、日记正文或日期。模型只描述能看见的内容，不猜人物身份与具体地点。建议名称可能不准确，低置信度时不采用，人工改名始终可用。

相同原件按内容哈希、模型、服务地址及命名协议版本在本机缓存，日期不进入缓存键。重复上传优先复用，单机并发请求合并；低置信度结果也缓存，避免反复尝试。视觉请求最多输出 128 Token，阿里云兼容地址关闭深度思考；其他服务需自行支持这些请求参数。请求失败不自动重试，附件保留，仍可保存日记。服务端响应里的实际 Token 和费用估算单独列为「图片命名」，缓存命中不生成一笔零费用假调用。

建议与人工名称写入 `entry_media.label`，随独立附件版本保存，悬停仍能查看原始名称。原件按哈希寻址，名字不改变磁盘文件；同一原件在不同日记的名字可以独立修正。历史下载绑定当时的名称与日期。便携备份保留这些关联名称；可重新生成的模型命名缓存不进入 ZIP，SQLite 快照仍包含它。

## 原文、排布与原件

- `journal.sqlite3` 保留文字、附件元数据和排布历史。排布按 Unicode 码点定位，表情不会使 Python 与浏览器的文字位置错位；同位置附件保留顺序。
- `media/<哈希前两位>/<SHA-256>.<类型>` 保留不可变原件。重复内容只占一份物理文件，但在不同日期或日记中仍是独立的出现，不合并成长经历。
- 上传以分块方式写入暂存文件，完整写入并识别类型后原子发布。浏览器草稿只保存成功上传的附件编号与位置，不存 Base64 大文件。上传失败时阻止保存不完整附件，文字仍可恢复；未完成上传的原件需要重新选择。
- 文字版本与附件版本独立。单独增删或移动附件只更新排布，不改变文字版本、分析、行动、成长缓存或任务票据；也不丢弃已在途的文字分析。移除的附件在该日记历史中仍可回看。删除整条日记后释放无其他记录引用的原件，已存在的备份仍可恢复。

## 隐私与费用

附件原件、文件名、路径与哈希不进入 AI 输入。正文是否分析沿用记录的 AI 开关，不隐含对图片和视频的识别或计费。图片智能命名另行开启后，只有小尺寸预览进入独立视觉请求，不进入文字整理上下文。自动化测试检查实际 Worker 输入与请求次数，不以字符串长度估算图片 Token。

本地 HTTP 播放接口保留 Host、Origin 与跨站请求检查，使用独立且按端口区分的 HttpOnly / SameSite=Strict Cookie。此 Cookie 仅用于读取附件，不能替代修改接口的请求头令牌，也不放在分享链接或查询参数中。读取按字节范围返回，支持 HEAD、206 与 416；播放不将整个视频放入 JavaScript 内存。页面不使用外部媒体 CDN。

## 可带走、可恢复的备份

「导出完整备份」下载 ZIP：`diary.json` 加上所有当前及历史引用的 `media/` 原件。压缩包对媒体不做重复压缩；元数据压缩，内容按哈希去重。API 流式发送，避免浏览器先缓存整个视频集合。未保存的上传草稿不进入正式导出。导入前检查路径白名单、重复成员、文件类型、大小与 SHA-256，并在隔离暂存目录完成校验；确认后才合并或替换数据库。合并保留本机已有日记与排布，附件 ID 冲突时重新分配，避免绑定到另一张照片。

自动 SQLite 快照的备份目录同时有一个共享的 `media/` 镜像。原件只复制一次；不要只搬走 SQLite 文件，要一起带走镜像目录，或选择 ZIP 导出。删除旧快照不会擅自删除其他快照可能引用的镜像。恢复先验证并补回原件，再事务导入；损坏备份不会替换日记。ZIP 最大 16 GB，JSON 元数据上限 30 MB，现有单表导入上限仍为 100,000 行。

数据库升级到 v5 前会保留 v1–v4 一致性快照；旧 JSON 和 SQLite 快照继续可导入，旧附件自动补充空名称，继续沿用原名。含附件的日记不提供伪装成完整备份的独立 JSON 导出；Markdown 明确只导出文字。费用账目仍独立保存，不随日记恢复倒退；API 密钥也不进入便携备份。备份内容未额外加密，请存放在自己控制的位置。
