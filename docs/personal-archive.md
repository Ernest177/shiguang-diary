# 关于我：把记录积累成可修正的理解

个人档案包含成长经历、记忆卡片、我的画像、月度回顾与成长足迹。原文完整保留，模型理解作为可修正的派生资料；不通过生活评分衡量用户。

## 不为改写而整理

默认“自动判断”：允许 AI 处理日记，不意味着必须为它再写一篇回顾。单条简短、段落少且没有明确表达困难时，本机直接呈现原话，仍从原有单条请求中提取行动和成长线索。长记录、多条需要合并的记录、明确提出表达困难的文字继续使用 AI。它是保守的请求选择规则，不是准确的语言质量评判器，用户仍可手动重新整理。

只有一两份资料时，画像不急着下结论，先展示来源原话或用户修正。默认至少三份独立来源、跨越两个日期或阶段后，才尝试生成跨记录理解；重复拆出的多张记忆卡不当作多份资料。这个条件只避免过早概括，不证明之后生成的理解必然有价值。自动呈现还会过滤只有单份来源支持的改写和高度相近的复述，记忆卡片及原文继续保留。

文字相似度默认 88%，在本机去除标点、统一字符形式后比较字符序列；明显更短的摘要不会仅因用词接近就换成更长原文。相似度不是语义等价、事实正确性或成长价值的分数，否定词和时间不能据此被删改。该阈值只控制展示，不修改原文、用户修正和行动状态；生成后过滤也不能退回已经发生的 Token，真正减少调用依靠生成前的按需规则。

比较范围是“AI 整理结果与它引用的用户原话”，不跨日期对成长经历去重，也不把 AI 生成的记忆摘要当成原文。原话预览只折叠同一条来源中逐字相同的引用；不同来源即使用词相同，也保留各自日期与出处，同一张记忆卡的多个来源可以分别呈现。预览最多显示三条节选，完整记录仍可在成长足迹和记忆来源中查看。

设置中的“按需整理”可改为始终使用 AI，或在折叠选项中调整 60–99% 的文字阈值、100–2,000 字符的简短记录上限。修改阈值只更新本机呈现，不自动付费重做历史；AI 勾选仍负责隐私范围，不要求用户逐条判断文字是否需要加工。

## 数据与授权

自动积累默认关闭。开启一次后，已有和以后的 AI 日记均可参与，无需用户判断哪条“值得授权”；`memory_exclusions` 保存主动排除的记录。日记自己的 `ai_enabled=false` 始终优先。旧的私密经历不会自动放开；开启后新补录经历的表单默认允许整理，也可取消。

原有手动模式继续使用 `memory_permissions`。关闭自动积累时保留已经参与的来源，不删除原文或档案。自动模式下暂停仅停止成长提取与档案额外请求，日记原有的 AI 整理仍遵循自身设置；所有云端处理依然会发送参与的必要原文片段，本地缓存不是云端永不接触原文的保证。

## 增量整理与费用

1. 新日记在普通单条请求内追加成长提取，不再为同一原文单独请求记忆。一次最多三条线索、两个成长片段，可为空。
2. 旧记录分成最多 4,000 字、重叠 200 字的片段，逐次调用并持久保存进度。开启后自动排队，暂停 / 继续接续进度。意外重启中的付费任务标为失败，手动重试前不重复调用。
3. `growth_receipts` 保存来源 ID、版本、内容签名、提取提示词版本、已处理片段、模型和时间。空结果也有回执；相同版本不重新处理。换模型不会自行清空历史缓存。
4. 新线索按来源增量加入；相同标题不自动视为相同含义。用户修正优先，删除指纹与引用哈希继续阻止重新引入。
5. 画像等待短时间合并更新，再使用节选记忆。历史较多时优先留一次当日请求生成阶段画像，避免历史处理占满额度而长期看不到档案。未变化的画像、月度回顾直接复用本地结果；页面浏览和成长足迹搜索不请求模型。

默认每天最多 12 次额外请求、每月参考预算 1 元，可在积累设置修改。上限覆盖 `growth`、`portrait`、`month`，按独立用量账目的本地日期计算，包含失败尝试；普通日记与每日回顾另计。新日记合并提取仍会增加该次输出 Token，不等于完全免费。

每次请求前检查已知估算费用，到达预算后暂停后续请求。单次调用可能超出剩余额度；服务缺失用量、折扣、阶梯定价也会影响估算，未知费用显示为未知，因此这不是提供方的硬性扣费上限。云端模型未设置单价时暂停额外请求；每日次数限制仍独立生效。失败不自动付费重试，用户点击更新才重试未完成片段。

本地回执长期保存到来源改变或删除，不依赖云端前缀缓存的短有效期或命中概率。当前没有向量数据库、语义搜索或跨设备同步；成长足迹是明确的本机关键词检索。

v1.4.1 进一步复用单条整理与每日回顾的成功结果，合并短时间内的每日请求，并精简重复输入。临时短编号只影响模型传输，原始 ID 和来源关系保留在本机。没有为节省 Token 删除原文，也没有用有限摘要替代成长足迹中的完整记录。

阿里云前缀缓存可作为补充，当前保留默认的隐式缓存与命中统计；不为日记额外配置显式缓存。根据[官方说明](https://help.aliyun.com/zh/model-studio/context-cache)，显式缓存有效期为 5 分钟，创建通常有额外开销，Qwen3.8-Flash 的折扣还需按控制台实际价格核对。日记请求可能相隔数小时，本地结果复用更符合这种使用节奏；不承诺云端缓存必然命中或套用通用折扣。

经历时间保留用户原话，可写“大学期间”“大约2019年”。成长足迹可查看全部原文，也可筛选模型提取的重要经历、转折和日常感受；未提取片段不代表原文被丢弃。日记按所属日期排列，模糊经历暂用补录时间排序，并保留模糊标记。月度回顾只采用时间明确到月份的资料。

## 四条验收标准

| 标准 | 实现与检查 |
| --- | --- |
| 经历有出处 | 每张卡片有当前已授权原文的连续引用、来源 ID 和版本；伪造引用或未知来源会被拒绝 |
| 推测有标记 | 新画像归纳统一为待确认；仅逐字复述用户已确认 / 修正记忆时可显示原话确认。近期线索带时间范围；模式至少两条来源 |
| 纠正能保留 | 重整未修改来源时，用户确认和修正的卡片保留；同一引用产生的改写卡片会被拦截；画像使用修正文本 |
| 删除能生效 | 来源修改、删除或排除后，整个依赖记忆及缓存报告撤回；上下文签名和任务票据阻止在途旧结果写回 |

用户删除记忆后，仅保留标题类别指纹与来源引用哈希，防止相同标题或同一逐字引用重新生成；原文和已有历史备份不会被一并删除。这不是完善的语义遗忘：改变标题与引用表达后仍可能生成相似理解，需继续人工审阅。

来源一旦改变，依赖该来源的卡片连同其确认 / 修正一起撤回，避免把用户决定挂在已经失效的依据上。其他来源未变化的修正继续保留。

## 画像与月度变化

画像只引用有效记忆卡片，展示关注、价值、偏好、能力线索和仍在探索的问题。自动模式最多选择 24 条、总计不超过 24,000 字符的记忆，混合用户修正、近期与较早的线索，标明本次覆盖范围。模型输入不重复携带整篇日记和原文引用。修正不截断后再当成完整结论，超出总输入上限的卡片不纳入本次节选。

自动模式的月度回顾复用已积累的原文引用，每月最多选择 10 份、每份最多 1,600 字符的片段；本月与上月一起不超过 20 份。它是节选回顾，不代表完整月份。比较项必须同时有两个时期的原文引用；无上月资料时只整理本月。模型不能把“节选里没出现”当作“没有发生”。手动模式仍使用已选原文，并保留单次输入范围检查。

每项理解可跳转到记忆与原文，也可以修正；未经认可不会标成已确认事实。引用存在不证明语义正确，不输出心理诊断、人格定论或人生评分，仍需在真实使用和独立评测中核对含义。

记忆、画像和月度提示词分别登记版本与哈希；画像缓存保存模型、提示词信息、上下文签名和时间。任何相关来源或反馈改变都会清除旧报告；生成任务完成前再次核对上下文与票据。

## 升级、导出与恢复

数据库和 JSON 备份版本为 3。首次打开版本 1 / 2 数据库时，在 `data/upgrade-backups/` 中创建完整性检查通过的升级前快照，再事务建表。已有原文、历史、行动与 AI 设置保留；自动积累默认关闭。

JSON 导出包含经历、记忆、来源、修正、遗忘指纹、单条排除与分片缓存。自动模式导出有效来源清单；导入不会启用自动积累或更改 AI 服务设置。支持 v1 / v2 / v3 JSON 与数据库快照；合并保留本机冲突，恢复后画像和月度缓存撤回，可复用来源缓存重建。费用账目独立保存，不随日记恢复回退。

旧程序无法直接读取 v3 数据库。回退前先导出新增记录，再结合升级快照恢复；当前没有一键降级向导，不应直接用旧数据库覆盖新数据。

## 验证范围

自动检查覆盖普通请求合并、空结果缓存、重复更新不调用、分片接续、暂停与排除的在途撤回、预算和每日上限、纠正与遗忘、节选输入上限、原文分页检索、私密来源隔离、升级快照与 v1 / v2 / v3 恢复、本机接口保护。前端合成状态检查进度、设置、搜索、翻页和转义。

11 个新增离线合约样例验证结构、引用、时间与待确认标记；使用手写响应，不能作为真实模型准确率。浏览器自动化工具当前不可用，本次未完成新的浏览器视觉与交互验收。真实 Aliyun 模型语义质量尚未评测。
